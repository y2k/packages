# Eval-тесты версионированных пакетов

## Цель

Добавить минимальный способ писать assertion-тесты для каждой версии пакета и
проверить его на `xml/0.4.0`. Тесты запускаются через `ly2k --target eval` без
отдельного test runner.

## Размещение и запуск

Тест версии пакета хранится в `<package>/<version>/test/<package>_test.clj`.
Вложенный каталог не загружается как часть пакета, потому что eval loader читает
только `.clj`-файлы непосредственно из каталога версии.

Тест объявляет отдельный namespace, подключает тестируемую версию через `deps`
и вызывает `(assert condition)`. Пример запуска:

```sh
ly2k --target eval < xml/0.4.0/test/xml_test.clj
```

## Поддержка evaluator

Eval stdlib получает функцию `assert` с одним аргументом. Truthy-значение
возвращает `true`; `false` или `nil` вызывают `Eval_error "assertion failed"`,
из-за чего CLI завершается с ненулевым кодом.

## Переносимый reduce по map

`reduce` должен одинаково работать с list и map на всех targets. Для map каждый
элемент передаётся callback как двухэлементный список `[key value]`. Eval уже
поддерживает этот контракт; JS и Java runtime приводятся к нему.

После этого `xml` передаёт `attrs` прямо в `reduce` и не вызывает
JS-специфичный `Object/entries`.

## XML-форматирование

Лишний строковый пробел перед `attrs_to_string` удаляется. Поскольку
`attrs_to_string` сам добавляет пробел перед каждым атрибутом, результатом будут
`<tag></tag>` для пустых attrs и `<tag id='x'></tag>` для непустых.

## Покрытие XML

Локальный тест содержит четыре проверки публичной функции `xml/to-string`:

- пустой элемент;
- один атрибут;
- текстовое содержимое;
- вложенный элемент.

Порядок нескольких атрибутов, escaping, test discovery и общий runner в эту
задачу не входят.
