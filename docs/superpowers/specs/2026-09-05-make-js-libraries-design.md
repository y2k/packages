# JS-библиотеки в DSL make

## Цель

Добавить в `make/0.6.0` минимальную поддержку явного списка библиотек из
репозитория packages. Выбранные библиотеки и JS runtime добавляются в каждое
настроенное дерево результатов.

## DSL

Конфигурация сохраняет существующие пары исходного каталога и каталога сборки и
получает map библиотек:

```clojure
(make/makefile
 {:target "js"
  :dirs [{:path "src" :build-dir ".wrangler/bin/src"}
         {:path "src" :build-dir ".wrangler/bin/test"}
         {:path "test" :build-dir ".wrangler/bin/test"}]
  :libs {:xml "0.4.0"}})
```

Одна исходная папка может компилироваться в несколько `:build-dir`, а несколько
исходных папок могут дополнять один `:build-dir`. Это сохраняет сценарий
spectator, где production и test используют разные деревья.

`make` компилирует только явно перечисленные библиотеки. Он не читает формы
`(deps ...)`, не разрешает транзитивные зависимости и не выбирает версии
автоматически.

## Исходники библиотек

Каждая запись `name -> version` преобразуется в source root:

```make
$(LY2K_PACKAGES_DIR)/name/version
```

Для каждой библиотеки и каждого уникального `:build-dir` создаётся отдельная
пара source/output. Иными словами, генератор раскрывает декартово произведение
`:libs` и уникальных каталогов сборки.

В library root рекурсивно выбираются `.clj`-файлы, кроме файлов во вложенных
каталогах `test/`. Это исключение не применяется к локальным `:dirs`: явно
указанная папка `test` должна продолжать компилироваться.

Выходной путь сохраняет относительный путь исходника и меняет расширение на
`.js`. Поэтому поддерживаются только пакеты с расположением файлов,
соответствующим namespace: например `xml.clj` для `xml` и
`effects_promise/fetch.clj` для `effects-promise.fetch`. Старые `main.clj` и
`index.clj` специально не поддерживаются; генератор не парсит namespace.

## JS runtime

Цель `build` также копирует:

```make
$(LY2K_PACKAGES_DIR)/prelude/1.0.0/js/language_runtime.js
```

в `<build-dir>/language_runtime.js` для каждого уникального `:build-dir`. Это
соответствует imports, которые генерирует текущий JS backend для корневых и
вложенных namespace.

Версия runtime фиксирована как `1.0.0`: отдельная настройка не нужна, пока не
появится вторая реально используемая версия.

## Сгенерированный Makefile

Makefile сохраняет текущую модель: `rwildcard`, список `OUT_FILES`, отдельное
правило stdin/stdout для каждого `.clj`, а также цели `all`, `build` и `clean`.
Директива `.DELETE_ON_ERROR` удаляет незавершённый output, если `ly2k` завершился
с ошибкой.

Изменения:

- существующие пары `:path`/`:build-dir` компилируются без изменений;
- каждая библиотека компилируется в каждый уникальный `:build-dir`;
- файлы под `test/` удаляются только из library roots;
- runtime входит в prerequisites цели `build` по одному разу на `:build-dir`;
- `clean` удаляет каждый уникальный `:build-dir`.

Одинаковые пары library/build-dir и одинаковые runtime rules не дублируются,
даже если несколько элементов `:dirs` используют один каталог сборки.

Порядок компиляции библиотек не задаётся: `ly2k --target js` не читает
скомпилированные imports, поэтому каждый модуль можно транспилировать независимо.

## Ошибки

Сгенерированный Makefile должен останавливаться с понятной ошибкой, если:

- `LY2K_PACKAGES_DIR` не задан;
- каталог явно указанной версии библиотеки отсутствует;
- отсутствует JS runtime.

Отсутствующие транзитивные зависимости и collisions одинаковых output paths не
проверяются генератором. Первые проявятся при загрузке JS-модуля, вторые остаются
ответственностью единого namespace layout.

## Проверка

Один golden assert в `make/0.6.0/test/make_test.clj` фиксирует публичный контракт
генератора:

- сохранение существующей формы `:dirs`;
- раскрытие `:libs` через `LY2K_PACKAGES_DIR`;
- компиляцию библиотеки во все уникальные `:build-dir`;
- исключение вложенного library `test/` без исключения локального `test`;
- одно правило копирования runtime на каждый уникальный `:build-dir`;
- проверки обязательных путей;
- удаление незавершённого output через `.DELETE_ON_ERROR`;
- удаление уникальных каталогов в `clean`.

Отдельный resolver, dependency graph, symlink-based `restore`, Java target,
`javac`, npm packaging и поддержка старого package layout в эту задачу не входят.
